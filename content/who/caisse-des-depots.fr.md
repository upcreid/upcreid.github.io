Un projet de migration de données pour une institution financière publique : sortir des décennies de données de systèmes legacy et les remettre dans une base Oracle propre, sans perdre une seule ligne. Moitié ingénieur, moitié traducteur entre le métier et les systèmes.

## Ce que j'y faisais

### Solutions analyst

- Scripts shell pour récupérer les données legacy (MVS, DB2, Oracle, Sybase, XML)
- Épurer, bonifier et remettre en forme les données avant chargement
- Les intégrer dans Oracle (référentiel, dérivations, flux bancaires)
- Compter et vérifier les données intégrées par rapport à la source
- Faire évoluer les transferts de fichiers sécurisés (CFT)
- Scripting batch pour mettre en forme les données automatiquement (WinSCP, Excel)
- Orchestrer les traitements avec Control-M
- Écrire et optimiser les requêtes SQL
- Packager le tout dans un repository SVN dédié (KSH, SQL, ENV)
- Former l'équipe à SVN et aux habitudes de livraison continue
- Créer des fonctions shell utilisées dans l'infrastructure CDC
- Valider les livrables (documents techniques, produit)

### Business analyst

- Animer des ateliers avec les équipes métier pour définir les règles de migration à partir de l'analyse de la source
- Analyser les données à migrer
- Définir la cinématique et les règles de migration
- Assister les équipes métier pendant la recette
- Définir les matrices de flux et configurer les outils de transfert
- Documenter et communiquer en français et en anglais

## Environnement technique

- CFT (SOPRA)
- Unix, KSH, Windows Server 2003, VBS, Citrix, Cisco
- Oracle, Sybase, MVS, DB2
- SVN, Quality Center, JIRA, Control-M
